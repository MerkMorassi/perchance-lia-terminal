## WHAT WAS THOUGHT

**The two trees were not rivals, they were two halves.** Neither tab held a superset: this workspace
had the RTFM, the folder-lane SYNC, the bigger README/TODO/CSS and 65 commands; the other tab had the
draft panel, the archive IMPORT/EXPORT-JSON pair, a voice nuance, two traits and an OAuth Drive sync.
So "which one is right" was the wrong question from the first minute, and the answer was never going
to be a choice. The union was.

**The one genuine collision was the two syncs, and it was resolved by keeping both.** The other tab's
`sync.js` was an EARLIER version of the same module - the Google Drive lane that our folder lane had
already replaced. Copying it over ours would have thrown away the newer folder road; discarding it
would have thrown away a working Drive road that had never been wrong, only superseded. So it was
**vendored** as a second module beside the first: `src/js/sync-cloud.js` (`window.cloudSync`), every
id it owns renamed `sy* -> gd*` so the two can never collide on one page, its own record key
(`kv: lia_settings / sync_cloud` - the folder road keeps `lia_settings / sync`), its command moved to
`/cloud`, and its section drawn at the foot of the SAME `#syncPanel`. Two roads, one panel, no shared
name. The alternative - a branch inside one module - would have left every id ambiguous forever.

**The order of work was forced by how the other tab's files can be read.** They are not at the
generator's own URL: the served iframe carries `<base href="https://perchance.org/<name>">`, and the
real storage is `https://user.uploads.dev/file/<key>`, with `<key>` in `#preloaded-generator-data` ->
`srcManifest[path].key`. Sixty files were pulled out that way and diffed against this tree. That is
the trick worth keeping: **the last SAVED state of any of his generators is readable from inside the
running page**, and a future session that needs to know what the server actually holds should reach
for the manifest rather than guess.

## WHAT WENT WRONG

**A save from the wrong tab is what made the mess visible, and it can happen again.** Patrikios saved
from the second tab, which pushed ITS tree at the server: `src/js/sync.js` was reverted there (his
62.5 KB folder lane replaced by the 24.9 KB Drive lane) and six files that had never been saved were
not on the server at all (`js/rtfm.js`, `js/rtfm-edit.js`, `rtfm/README.md`, `rtfm/commands.md`,
`rtfm/rtfm.json`, `rtfm/turn.md`). The lesson is not "do not use two tabs" - it is that a save is a
whole-tree overwrite, so **the tab that saves must be the tab that is current**. Do not save from the
stale one; it would overwrite this tree for the second time.

The other thing the diff showed is smaller and worth naming: a hand-kept list drifts. `backup.js`'s
`moduleCheck()` had a copy of the module list with its last ten entries missing, so a load that lost
one of those ten could not be seen. (That one is fixed - see `2026-09-26-the-second-ask.md`, where it
mattered.)
