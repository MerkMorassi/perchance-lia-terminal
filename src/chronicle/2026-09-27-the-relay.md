# THE RELAY

2026-09-27 - the session where the terminal was given a door out of the browser, and where the honest
answer to *can she read the web* was measured instead of assumed.

## WHAT HE SAID

> *"Can we grant internet access from within this application?"*

and then, when the answer was *yes, and it costs nothing but your quota*:

> *"Add it and we can figure out how to implement and leverage it for learning. Can we access wiki
> pages or when we want to RTFM on a new product of service?"*

Two things are being asked for. The narrow one is a **door**: can the page reach the internet at all.
The wide one is the reason for the door - **learning**, and specifically her and him learning a new
product or service from its own pages rather than from memory.

## WHAT WAS BUILT

One import line in `main.pjs`, beside `kv` / `generateText` / `generateImage`:

    superFetch = {import:super-fetch-plugin}

This is the **first change to `main.pjs`** since the terminal was built, and it is an import and
nothing else - no list, no logic, nothing that could be mistaken for a dimension of the shot list.
`src/pack/main.pjs.txt` (the pack's byte-exact copy of that file) was regenerated in the same pass so
the copy is still exact.

**It was not merely a library going onto a shelf.** `src/js/keys.js` already routed `mode: "proxy"`
through it, and `src/keys/providers.json` marks **Replicate** as proxy because Replicate refuses
browser-origin calls. So that road was wired and dead at the same time: with the import absent,
`request()` threw *"NEEDS THE RELAY (super-fetch-plugin), BUT IT IS NOT LOADED"*. The import closes
that gap, and it is the general keyless door any lane built later can use.

## WHAT WAS MEASURED

Everything below is a real call from the shipped page, not a claim from documentation.

- `https://en.wikipedia.org/wiki/Perchance` - 200, **52,604 B**, 454 ms. Raw article HTML, CORS-free.
- `https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API` - 200, **154,164 B**, 211 ms. So a
  product's own documentation is reachable by URL, with no key of any kind.
- The MediaWiki action API with `prop=extracts&explaintext=1` - 200, **34,067 B** for *Claude
  Shannon*, and it is the **whole article as plain text**. No HTML, no navigation, nothing to strip.
- `https://r.jina.ai/<url>` - the MDN page as clean **markdown, 6,317 B**: the article with none of
  the site around it. Free, third-party, rate-limited; the one road here that is not a source or a
  provider.

## WHAT WAS THOUGHT

**The door was already half-built, and nobody had noticed.** Reading `keys.js` while answering the
question was what turned "we could add this" into "we are missing this": a proxy route was sitting in
the key ring with no relay behind it. That is worth doing for its own sake, independent of any web
lane - a provider that refuses this origin was, until now, simply unusable.

**A page is not a document.** The measurement that matters is the ugly one: the MDN page is 154 KB of
HTML and a naive tag-strip leaves 5,757 characters - about 1,440 tokens - **with the site's navigation
still in it**. Raw HTML runs 20-30x the prose it carries, so "read this URL" is really "fetch, extract,
trim", and only the last two make it usable. Hence the order recorded in `src/README.md`: a source that
already publishes text (the MediaWiki API, a docs repo's `.md`, an RSS feed) beats an extractor run on
HTML (readability), which beats a reader service. This also decides how the lane must be built: what
arrives has to be trimmed to what her turn can hold, and the honest failure mode - *nothing
extractable came back* - has to be sayable, because a JavaScript-built page returns an empty shell and
should not be handed to her as if it were content.

**Restraint about her.** It would have been easy to hand her a `[[FETCH: ...]]` line in the same
session. It was deliberately not done: a capability she can be told to use belongs in
`src/lorepack/capabilities.md` - the briefing she reads about her own powers - and that document must
not describe a lane that does not exist. The import is his, today; the lane is a decision, and the
shape proposed for it (her `[[FETCH: ...]]` answered like `[[READ: ...]]` with the same receipts, the
result offered to the LOREPACK so it is recalled and focusable, plus `/web <url>` for his own hands)
is written down in `src/TODO.md` §1br rather than guessed at.

**And the RTFM.** He asked about it by name, so the answer belongs here: yes - a product's own docs
are reachable by URL, and the natural second step is that a page pulled in this way can become a new
`src/rtfm/` page or a pack document, so a service can be learned from the primary source. That is a
build, not a setting, and it is left open on purpose.

## WHAT IT LEAVES OPEN

No lane is wired: nothing calls `superFetch` except the key ring's proxy road. There is no
`[[FETCH: ...]]`, no URL-to-LOREPACK import, no `/web`, and **no search engine** - a URL must be
named, and DuckDuckGo-by-scrape is possible and fragile, which is said plainly so it is never
assumed. Out of reach through this door: logins and paywalls, pages built by JavaScript, and targets
whose bot protection refuses the relay. The quota it spends is his own.
